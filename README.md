# Voice Atelier — Song Studio v0.2.0

歌詞からボーカル曲を作り始めるための、端末内処理を基本とするiPad向けWebアプリ試作版です。

**Netlify不要、Netlifyクレジット不要**。外部AI・CDN・外部音声処理APIは使っていません。

## 搭載機能

- デフォルトの5ブロック：**Aメロ / Bメロ / Cメロ / サビ / ラスサビ**。任意のブロック追加・削除・名前変更ができます。
- 各ブロックに長文の歌詞を入力。小節数（1〜48）、開始小節（小数も可）、開始位置を拍単位のスライダー・タイムラインのドラッグで調整可能。
- BPM（40〜240）・拍子（3/4・4/4・6/4）に基づくメトロノーム。音のON/OFF・音量・再生中の拍点灯。録音前1小節カウントあり。
- ブロックごとに録音（最大180秒/テイク）。従来の音を上書きしないでテイクとして追加。
- リード／ハモリ上／ハモリ下／ダブル＋任意のレイヤー（最大24レイヤー）。最大160クリップ（端末性能・空き容量による実質上限あり）。
- 複数録音を同時再生。M/S、音量、左右バランス、クリップのミュート、原音WAVの書き出し、クリップ別音量調整、時間の微調整（±0.05秒）。
- ブロック全体はドラッグまたは開始小節を入力して配置変更。録音クリップは各ブロックに紐づいて一緒に移動し、個別に時間ずれを調整可能。
- 音質補正：HPF、無音部ノイズゲート、3帯域EQ、歯擦音抑制EQ、コンプレッサー、リバーブ。自然／温かい／明瞭／ラジオ風プリセット。
- **24bitステレオWAV**の曲全体を書き出し（最大8分）。歌詞・構成・各録音の音声データが入った**ZIPバックアップ作成・復元**。
- SafariのIndexedDBへのローカル自動保存。Service Workerによるアプリ画面のオフラインキャッシュ。

## 無料・NetlifyなしでiPadに導入する手順

GitHub Pagesを利用します。GitHub PagesはGitHub Freeの**公開リポジトリ**で利用できます。ホスティング自体を使いたくない場合は、マイク許可とバックグラウンド処理の制約があるためWeb版ではなくSwift/Swift Playgroundsによるネイティブアプリが必要です（このZIPはネイティブアプリではありません）。

1. `VoiceAtelier-SongStudio-v0.2.0.zip` を解凍し、このREADMEと同じ階層にある **`index.html`, `styles.css`, `app.js`, `capture-worklet.js`, `sw.js`, `manifest.webmanifest`, `icon.svg`** の7ファイルを確認。
2. GitHubで **新しい** 公開リポジトリ（例：`voice-atelier-song-studio`）を作成。**既存のKotoba Writerや音楽アプリのリポジトリは使わないでください。**
3. リポジトリ内の `Add file` → `Upload files` から7ファイルを一度に追加してコミット（ZIPのままではなく解凍したファイルをアップロード）。`README.md` は任意です。
4. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Source: Deploy from a branch` → `Branch: main` と `/(root)` → `Save`。
5. GitHub Pagesの公開URL（通常 `https://GitHubユーザー名.github.io/リポジトリ名/`）を **iPad Safari** で開く。マイク録音を許可。
6. Safariの共有から「ホーム画面に追加」。アプリを一度オンラインで完全表示した後は、アプリのファイルがキャッシュに残っていればオフラインで画面を開いて利用できます。

**重要：** iPad Safariの `file://` URL、ZIP内ファイルのプレビュー、ブラウザーの非HTTPSページからはマイクが使えない場合があります。そのため、インストール時のHTTPS公開は必要です。GitHub PagesはNetlifyと別サービスで、Netlifyのクレジットは一切消費しません。

## 音声・権利・セキュリティ

- このアプリには外部アップロード用API、アカウント認証、利用分析SDKを実装していません。録音・歌詞はブラウザー内のIndexedDBに保存し、GitHubリポジトリにはアップロードしません。
- GitHubの公開リポジトリでは**アプリのソースコードが他者から見える**ことに注意。GitHub Pagesのページアクセス自体にはGitHubのサービス運営上のログ等があります。
- Safariのサイトデータの消去・アプリ削除・URL変更・キャッシュ整理・OSのストレージ管理により自動保存内容が失われることがあります。**編集の区切りごとに「プロジェクト一式ZIPで保存」し、「ファイル」アプリに保管してください。**
- ZIPバックアップはこのアプリが生成する**無圧縮ZIP**に対応しています。一般的な圧縮ZIPの読み込みはサポートしていません。
- 以前Netlifyで動かしていたVoice Atelierの保存データは、新しいGitHub Pages URLでは自動移行しません。旧サイトでWAVを書き出し、このアプリに取り込んでください。

## 実装上の制約

- 録音はブラウザーのAudioWorklet（未対応時はScriptProcessor）経由の単一チャンネルPCM。入力端末の実ビット深度、OS側の音声補正、マイク音質、入出力遅延を直接制御できるわけではありません。
- 24bitは**WAV書き出しの量子化形式**であって、マイク入力そのものが24bitであることを保証しません。
- 録音と再生時はヘッドホンを使用。Bluetoothは遅延が大きい場合があるため、重要なハモリ録音時は有線推奨。クリップの「ブロック内の開始ずれ」でタイミングを補正できます。
- 歌声に重なったノイズを機械学習で分離する機能、ピッチ自動補正、音声の時間伸縮、曲の自動作曲、ドラムやMIDI伴奏は**未実装**です。BPM変更による既録音の自動伸縮も未実装です。
- 端末メモリに多くの音声を展開するため、録音・曲が長いほどiPadで負荷が高くなります。クリップは最大160でも、物理的に160件録音・再生できることを保証しません。
- Safariのバックグラウンドや画面ロック時に録音が中断されることがあります。
- GitHub Pagesの利用規約や使用制限に従ってください。公開リポジトリのGitHub Freeは私的・個人利用の試作版に適しています。商用SaaS等へのホスティングには制限があります。

## 検証状況

- Chromiumのページ環境でUI起動、ブロックとレイヤーの追加、歌詞、BPM、WAV取り込み、波形、クリップの時間ずれ、再生、録音の代替処理（疑似マイク）、WAVミックス書き出し、プロジェクトZIP書き出しとZIP復元の試験済み。
- JavaScript構文チェックを実施。
- この環境のブラウザはローカルサーバーへの画面アクセスが管理制限で遮断されるため、**iPad Safari実機のマイク使用、HTTPS経由のAudioWorklet実行、GitHub Pagesの設置後のService Workerオフライン挙動は未検証**です。実機で数秒録音し、再生・保存・復元まで確認してから大事な曲に使用してください。
